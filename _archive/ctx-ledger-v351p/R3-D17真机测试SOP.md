## 1. 一对一回归（确认老的没坏）

1. 给任意一位 TA 发一条消息，等回复。
2. 长按 TA 的回复 → 面板里应出现 **「上下文」行**（形如 `4 组 · 占比最高 功能与规则 ›`）→ 点开是 4 列表格。
3. 水水对话框输入：`上下文账本` → 应看到最近 6 轮报告，最新一轮的 `who` 是这位 TA。

**通过标准**：报告结构、面板行与 ?v=16 时一致（这是回归项，不该有任何变化）。

## 2. 群聊账本（新功能①）

1. 打开一个**群聊**（至少两位 AI 成员），发一条消息（可以 @ 某位，也可以不 @）。
2. 等成员们回完（导演模式挑人，可能一位也可能多位）。
3. 水水输入 `上下文账本` → 报告里应出现**成员名**开头的轮次（`who`＝发言成员，不是你的 TA 主号）。
4. 长按**某位成员的回复** → 「上下文」行 → 展开表格。

**通过标准**：
- 群轮报告里 **「功能与规则」组明显偏大**（【群聊规则】整块在这里，含群公告）——这是群路径的属性，不是错误；
- 「前序历史」组带 `· N 条`（群窗口条数）；
- 多位成员发言＝多份轮次（一人一份，符合设计）；
- 表格能正常展开、无排版错位。

## 3. 主动开口账本（新功能②，重点）

主动开口由**每分钟一次的心跳巡检**触发，要同时满足一堆条件。按下面配置，把路清直：

### 3.1 事前设置（都在「设置」里）

| 设置 | 值 | 为什么 |
|---|---|---|
| 主动消息总开关 | **开** | 心跳第一道门 |
| 模式 | **固定间隔**（不要随机） | 随机模式还要碰时段＋概率 |
| 间隔 | **拉到最小（3 分钟）** | 等待下限 |
| 勿扰时段 | **关** | 否则整段跳过 |
| 打开后安静时长 | **0 或最小** | 否则要等这段过完 |
| 定时推送改发动态（hbPost） | **关** | 开着且该 TA 有 Beyond 自动发布，火会烧到发动态去，不开口 |
| 留笺（hbNote） | **关** | 开着可能写张便笺就返回，不开口 |

再到该好友的配置页，确认 **「主动消息」没被单独关掉**（每位好友有独立开关）。

### 3.2 触发动作

1. 打开**你最近聊过的那个 1:1 对话**（心跳目标＝当前可见的 1:1，否则取最近聊过的）。
2. **保持这个页面在前台可见**（心跳要求页面可见；Android Edge 别切后台）。
3. **至少 3 分钟不发任何消息**（对话安静时长要够一个间隔）。
4. **也别在输入框里打字**（有输入会挡 90 秒）。
5. 等：心跳每 60 秒扫一次，条件齐了最多再等 60 秒，TA 会**主动发来 1–3 条短消息**（屏幕底部弹 `TA 给你发来一条消息` 提示）。

### 3.3 验证

1. 水水输入 `上下文账本` → 最新一轮的 `who` 是这位 TA（时间就是刚才）。
2. **长按这条主动消息 → 面板里「不应该」出现「上下文」行**（D17.1 裁定：上游无 Token 行，账本行不渲染；有反倒是回归）。账本仍然记着——去第 1 步的报告里确认这一轮在。

**通过标准**：
- 主动轮在水水报告里出现且 `总` 有数字（API 返回的真值，说明 usage 回填成功）；
- 主动消息的详情面板**无**「上下文」行（其余行与上游原版一致）；
- **「功能与规则」组很可能显示 0**（主动请求不带工具块和协议区——这是路径属性，草稿里写明的，不是漏采）；
- 「前序历史」组偏小（只带最近几条聊天作背景）；
- 「动态资料」组含时间戳和开口指令行。

**可能遇到的情况（都不是错误）**：
- 等到的是**来电邀请**而不是文字（通话设置开着时有 1/3 概率）——长按那条消息同样有账本行；
- 主动轮可能 1 条也可能是 2–3 条（连发），每条形同的一份账本；
- 心跳开火前你恰好发了消息 → 这轮作废（撞车保护），下次间隔后再来。
