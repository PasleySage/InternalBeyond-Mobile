# 长按面板那一行：写什么、点开是什么

Type: prototype
Status: resolved（2026-10-14；A 路径：openMsgInfo 面板内行级展开）
Blocked by: 04 ✅（2026-10-14 resolved）

## Question

长按消息面板（`openMsgInfo` `:8867`）已有几行：发送时间 / 字符数 / 图片 / 附件 / 语音 / Token / 缓存命中率 / 记忆 / 来源。加一行「上下文」，要答：

1. **折叠态那一行写什么** —— 面板里每行是 `label / value` 两列（`mi-grid`）。候选：
   - `上下文 · 6 块 · 约 78.4k`（给总量 + 块数）
   - `上下文 · 历史 78% ›`（直接给最大块，用户一眼看到大头）
   - `上下文 · 记忆 1.2万 ›`（同上一条，但突出记忆）
   - 后两条更像「点开是为了解决什么」；第一条更完整但不指向。
2. **点开是什么** —— 已定这里可以用**真表格**（`mi-grid` 本来就是两列）。注：Markdown 渲染器在当前基线 9ae7034a 也已能渲染 table（旧版基线曾不渲染，2026-10-14 实跑验证；水水气泡仍按形态一致性走列表，与本面板无关）。但表格要能放下6 组 × 3 列（组名 / 字符 / 估算 tok / 占比），在手机宽度下挤不挤？需不需要把「预览 150 字」放在表格下面单独一块？
3. **面板现有行的排版规律** —— 现在是纯 `mi-row`（一行 label + 一个 value）。加一个可展开的行是**新交互**（项目铁律说不新造视觉，但可展开算不算？）。备选：加一个 `mi-btn`（面板底部已有按钮组：引用 / 复制 / 收藏 / 选择消息 / 修改消息 / 重新生成 / 删除），点它打开一个已有样式的 sheet。
4. **点开后要不要给「怎么省」** —— 同 map 的待决项。若给，写在哪：表格下方一句话，还是表格里加一列「可调」？

## 为什么这张票与 06 分开

06 在水水抽屉（AI 的地盘，跨轮、看趋势），这一处在消息详情（用户的这一条消息，就地看）。**两处的使用场景不同**——水水是「刚才那几轮怎么回事」，面板是「这条消息当时发了什么」。同一个数据，两种问法，措辞不该一样。

## 约束

- 老消息无快照时，这行**自动不显示**（沿用 `usage` 行的既有做法）。
- 不新造 sheet 样式：若需点开，复用 `openSheet` 已有容器。
- 折叠态那一行是唯一长期可见的元素——**它是用户会不会点开的全部理由**，措辞值得反复推敲。

## Answer（2026-10-14 定稿）

**Q1 折叠态那一行写什么** —— `上下文 · 4 组 · 占比最高 前序历史 ›`。（**2026-10-17 B 裁更新**：原「实测 34.4k」体积数字已移除，原因见下条。）
- **不写体积数字**（**2026-10-17 B 裁**，推翻 2026-10-16 甲裁）：真机复测暴露认知割裂——缓存命中时面板行显「实测 2.5k」，点开表格里却是历史 128k，用户完全懵。体积由面板既有 Token 行交代（「入」＝usage.i），面板行再显一个数只会和表格估算对不齐；故折叠行只给结构。分块的字/tok 仍标「约」。
- 「4 组」＝当轮**非零组数**（不是固定 6），与表内非零行自洽；「占比最高 前序历史」按补测事实（用户账号存量起大头是历史）；全零组时省略「占比最高」子句（只显「N 组」，不出空悬）。
- 行末 `›` 作展开暗示，与措辞一体。

**Q2 点开是什么** —— **行内展开**（点行 → 表格在原位出现，再点收起）。4 列表格：组 / 字 / tok / 占比（按字算；列头不标「约」，估算说明由表下注记「字/tok 均为约估算值。」统一承担）。**复用 `.mdr table`**（外层须 `.mdr` div，基线 9ae7034a 已含 table 渲染分支）；不放 head；敏感块（记忆/日历/Beyond/信箱）只答「多大」＋表格下方一句「具体内容去对应页面看」；表格下方另给一句「想少发一点」方向建议（见 Q4）。360px 下表满宽不挤（原型实测）。

**Q3 铁律问题** —— **已裁：走 A（行内展开），作为铁律① 唯一例外**（`openMsgInfo` 面板即详情视图——用户主动打开＝主动探索，行级展开是「详情中的详情」，语义一致；**例外唯一、不外延**至水水气泡/聊天主界面等其它容器）。理由：五路径原型对比（现状基线/A/B1/B2/C/D）——A 效果最佳（1 击展开、上下文行与表格一体、视线不跳），代价为 +5 条 CSS＋约 10 行 JS；B1（按钮换表格）零新 CSS 但 2 击＋1 返回、入口混在动作按钮组；C（表格常驻）面板必滚动；D（只加总量行）`›` 不可点有误导。铁律修订措辞见 map Notes 硬约束第 1 条（「唯一例外」段）与下方「设计取舍」。

**Q4 「怎么省」** —— **给**，只在表格下方一句**方向性建议，不写具体数值**（例：「下一轮想省，可调小上下文条数；不用的能力关掉，功能与规则会整块变小」）。

## 设计取舍（供上游了解：铁律①修订不是随手加的）

- **为什么允许行内展开**：`openMsgInfo` 面板本身就是「详情视图」——用户长按消息＝主动探索这条消息当时发了什么；行级展开是「详情中的详情」，与面板语义一致，不是把折叠交互引入聊天主流程。
- **为什么「唯一例外、不外延」**：折叠交互若全放开＝scope 扩张（以后所有诊断信息都可援引此先例要求行内展开）。因此铁律保留为「不新造折叠交互」，仅此一处豁免，水水气泡、聊天主界面等其它容器仍不造折叠。
- **决策过程**：五路径原型对比（A 行内展开 / B1 同 sheet 换表格 / B2 新 sheet 元素 / C 表格常驻 / D 只加总量行）＋A 深度原型（四维设计：单选一次一行／整行可点＋`›` 暗示／原位展开／再点收起＋重开重置）＋360px 三态验证（折叠/展开/无快照）后由用户裁决采纳。
