# r6 / r7 补丁链现状说明（2026-10-19 登记）

## 链的组成

| 文件 | 角色 |
|---|---|
| `_patch_engine.js`（工作区根） | 补丁引擎：锚点匹配＋替换，从干净上游原文重放 |
| `_patch_r6_summary.js`（根） | r6「摘要修复」补丁清单（数据） |
| `_patch_r7_startup_wait.js`（根） | r7「启动等待」补丁清单（数据） |
| `_mk_mirror.js`（根） | 链式生成器：按 `needs` 依次应用全部补丁清单，产出镜像版 `index.html` |
| `_mk_summary_patch.js`（根） | 单补丁生成器（只应用 r6，产出摘要修复 diff） |

## 现状：功能已上游化，链降级为方法学资产

- **r6「摘要修复」**：已被作者采纳（上游 issue #5 closed、PR #6 closed、v246-p 落地）。
- **r7「启动等待」**：已被作者采纳（上游 issue #8 closed、PR #9 closed）；且 2026-10-09 V3.0「纯上游」同步时，用户定 fix-r6 / fix-r7 **留档不叠回**，两补丁已撤出镜像。
- **「生成镜像」的现行路线**不是这条链：账本功能版用 `_deploy_ctx_ledger.js` 推，纯上游同步用 `_sync_mirror.js`。

## 为什么保留不删

1. **引擎＋清单是「新增补丁只写清单、不改引擎」纪律的载体**——方法学资产，删了纪律就没了抓手。
2. `_mk_mirror.js` 仍是 `docs\workspace-readme.md` 登记的「生成镜像产物」入口，可随时重放历史补丁做对照。
3. 链上五个文件靠相对 `require('./…')` 互锁，**必须同目录整体存活**（拆开即断）。

## 什么时候可以退场

上游某次发版后补丁锚点全部失效、且连续两个大版本都没有新增补丁需求时，按 `_retired\` 的维护约定整链退役（做法若仍值得保留，先搬进文档）。
