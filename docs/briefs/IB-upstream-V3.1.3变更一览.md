## ⚠️ 合并提示：上游把「上下文账本」整个采纳了（v353-p 起）——与本地补丁全面重叠，必须二选一

区间两枚提交只动 `index.html`。`cc7b9302`（V3.1.2）一枚装进上游自己的 **v352-p→v359-p 八个内部版本**；`4649aaa7`（V3.1.3）只是发送键换纸飞机＋版本号＋一处 CSS。最大的一件事：**作者把我们的「上下文账本」提案（issue #14，已关闭）整个实现了**——diff 注释里 `v353-p`／`v355-p`／`v356-p` 三处标记就是采纳痕迹。

**重叠判定（形态 A）：同一功能、同名同键。**上游新版自带 `<script id="ib-ctx-ledger">` 模块本体（11,714 B）＋三处调用点（genReply 的 `dm.*` 14 块、群聊 `grp.*` 22 块、主动开口 `hb.*` 16 块）＋消息面板行＋水水直答＋备份排除。接口 `begin/noteSave/readLast/reportM/rowHtml/detailHtml`、注册键 `apiSettings.ibCtxLedger`、消息字段 `m.ctxSnap`、500 轮上限、`N_TURNS=6` **与我们逐项相同**。我方本地的 80 个 hunk（模块 243 行＋调用点＋面板行＋CSS＋水水钩子＋测试钩子）落在同一批函数、同一批锚点上——不是「撞车」，是**整个功能被上游重做了一遍**。

**硬不兼容（关键）**：上游调用点会用句柄的 `_ctxT.tk()`／`tk2()`／`img()`（附言下标测量、图片张数）——我们的 `begin()` 句柄**没有这三个方法**。若保留我们的模块去配上上游的调用点，`_ctxT.tk` 一调就 TypeError，被 genReply 的 catch 吞成「连接中断」——**回复直接发不出去**。所以不存在「模块留我们、埋点用上游」的混搭，必须整体二选一。推荐：**用上游版**（它就是作者实现的同一功能，后续改进都走上游）。

**我方四项本地裁定与上游实现的差异（决策点）**：① D17.1「主动消息不渲染面板行」——上游改为渲染；且 v360-p 起主动消息本身有 usage 与 Token 行（我们当时「独行突兀」的前提已消失）；② D18.1「群聊条数测合并前」——上游用 `addHist(messages, mapped.length)` 第二参数实现，同结果、不同机制；③ 用户视图：面板行文案（「N 组 · 占比最高 X」→「X最多 · Y%」）、展开形态（四格表→六行列表）、组名（前序历史→对话历史等三处）、水水触发词（新增「输入构成」）；④ 我方三条测试钩子（上下文空态A/B/示例）上游没有，且上游模块不导出 `EMPTY_A/EMPTY_B`。

口径：`DB_VER` **16 未变** ⇒ 无库升级；`ib-sw.js` blob `6f48fcbb` **未变** ⇒ 不需重新缓存；本地已落的账本数据（`m.ctxSnap`＋registry）上游模块**直接可读**（形状差异良性，渲染只取共有字段）；无任何测试脚本断言账本代码内容 ⇒ 换基不打断回归。本一览只读预览，未对任何仓库做写操作。
