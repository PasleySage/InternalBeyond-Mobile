本轮 7 个提交里 6 个是 README 与头图素材的先删后加，真正的大头是最后一枚 `16f1bfea`（`index.html` **+7868 −763**，3,669,901 → 4,833,098 字节，涨 31.7%），应用内版本 `v310-p` → `v341-p`、`DB_VER` 15 → 16。两条主线：**Map 世界地图与环球旅行**（全新第 16 个模块，含地球仪、让 TA 出游、穿越年代、游记与纪念卡、行迹与分享、查地名）与 **记忆系统 AGB**（召回规则整套重做成八条、Gazing Back 回望标、向量检索、余温、档案牵记忆库）。另有作者自称的 v339「修网页版漏掉的几处」。

需要点明两处口径：① README「最近更新」是**累计稿**——「导入官方聊天记录」「调色盘扩展」「美化码与主题方案」「收藏夹」「通话配色与信封」五条在基线里计数几乎不变（导入官方 7→7、纸墙 4→4），属**沿用描述**，不计入本轮条目；② v339 说的「前情提要（封一章 / 保存 / 清空 / 每轮带给 TA）」，从我们的基线看是**整块新增**（基线 `_chapGetM`、「前情提要」均 0 命中），不只是修按钮。另外 Map 是首个吃外部地图服务的模块（高德 / OSM / CARTO / Nominatim），`CSP` 未变（`img-src *`、`connect-src *` 已放行），但**Key 与跨域要真机实测**。

## 合并方案（推荐顺序）

1. **先定 cdiag 的去留（本轮唯一决策点）。** cdiag 是排查「提示缓存为什么没命中 / 这轮上下文装了多少条」用的临时诊断面板，不是日常功能。两个选项：**（甲）暂不重放**——把 3 个 cdiag 提交留在旧 ref 上做留档，镜像树直接取上游 `16f1bfea`，等 V3.0 跑顺了再决定；**（乙）重放**——按新版重打 4 处、保留 2 处。**推荐甲**：V3.0 改动量是上轮的 13 倍，先用纯上游跑一轮真机，诊断面板要用时再叠。
2. **同步动作（选甲）**：在镜像上建一个**同步提交**，树＝上游 `16f1bfea` ＋ 镜像专属 `ib-ver.html`，从 `2c063430` 推上 `main`。镜像有本地提交 ⇒ **不能走 `PATCH ref` 快进**，必须走 trees/commit API 建提交；推完回读 main、等 Pages `built`、线上 `index.html` 与上游原文**逐字节**比对。
3. **选乙时的重放清单**：可干净重放 2 处 —— 消息详情面板的「上下文」行（`Token` 行原样，上游在其后新加了缓存命中率与记忆两行）、缓存基线记条数与问答文案；需重打 4 处 —— 消息时间脚注（与 Gazing Back 撞同一行）、历史来源区分、`saveAi` 传 `ctxStat`、缓存基线断点片段。重放前先跑 `Android\_test_ib_structure.js` 与锚点核对。
4. **副作用**：`IB_VER` `v310-p` → `v341-p`；`DB_VER` 15 → 16 ⇒ **首启走一次库升级**（新增 `memVec` 表，**不在** `SYNC_STORES`、**不进备份**，纯本地向量指纹）；`ib-sw.js` blob 未变 ⇒ SW 脚本不用重缓，但 `index.html` 变了首启仍需联网取一次新页且文件大 31.7%；设置页「置顶」那行说明文字还写着「最多 7 条」，**实际已是 20 条**（文案未同步，上游自己的小疏漏）。
5. **复测清单（真机）**：① Map —— 地球仪拖动 / 缩放变平面图 / 五款样式 / 换瓦片源、聊天 + 号出「环球旅行」三种玩法发一条看 TA 写不写游记、穿越年代挑公元前 3000、游记页存到 Blog、行迹打卡与「只我自己看」、高德 Key 填与不填两种情况；② AGB —— 同一位 TA 连发 3～5 条看 Gazing Back 数字、点开清单、标「不相关」、置顶 8 条以上看提示、余温开关开关各一轮、向量检索开与不开、删对话后回看摘要与前情提要；③ 复测项 —— 前情提要「封一章 / 保存 / 清空 / 每轮带给 TA」四个键、对话摘要保存与清空、缓存命中率是否显示；④ `DB_VER` 升级后老库能否打开、备份导出再导入一轮。
6. **保持警惕**：别让镜像变成「两边各修一份」的分叉；`cdiag` 若重放，要在提交说明里写明「镜像专用诊断补丁，提上游的 PR 不含这一处」——沿用上轮 `v310-p-cdiag` 的做法。上游若日后采纳某项，要撤掉对应重放。
