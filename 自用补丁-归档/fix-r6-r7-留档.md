## fix-r6 · 摘要修复

**用途**：修两件事——① 摘要请求的输出预算被思维链吃光（DeepSeek 两档默认开思考）；② 摘要失败时每个出口都说真因，不再一律「未生成：消息不足或 API 不可用」。

**锚点（13 处，H1–H11）**：

| 锚点 | 内容 |
|---|---|
| H1 | 摘要请求带 `_noThink:true`（关思考） |
| H2 | OpenAI 兼容分支：命中 DeepSeek 目标时下发 `thinking:{type:'disabled'}` |
| H3a | 空正文时按 `finish` 记真因（length 截断 / 真空两种说法） |
| H3b | 新增模块级 `_sumLastErrM`（真因链） |
| H3c | 「立即更新」的提示直接显示真因（不再套「未生成：」前缀） |
| H4 | 并发早退给真话（「摘要正在整理中…」）；每次尝试先清空上一次的真因 |
| H5 | 「已经没什么要补的」这条早退给真话（**文案由用户定稿**） |
| H6k | 摘要未启用给真因（指向 API 页开关） |
| H7 | 频道记录读不到给真因 |
| H8 | 读窗口失败给真因 |
| H9 | 没有可用 Key 给真因（指向 API 页） |
| H10 | 整理期间封档线变了给真因 |
| H11 | 镜像专用版本标记 `v262-p-r6`（`mirrorOnly`，提上游的 PR 不含这一处） |

**用户可见文案（原样保留）**：
- 「摘要已是最新：暂时没有要补的内容（再聊多些，会自动跟上）」—— H5，用户定稿
- 「摘要没写出来：模型把输出预算用在思考上了（finish=length，可换个不带思考的模型执笔）」
- 「摘要没写出来：正文是空的（finish=…），可稍后再试」
- 「摘要正在整理中，稍等十几秒再点一次」
- 「对话摘要没有开启：API 页 → 全局设置 → 对话摘要 里打开」
- 「读不到这个频道的记录：退出去重进一次再试」
- 「摘要用的 API 没填 Key，去 API 页补上就能用」
- 「这次整理作废了：期间封档位置变了，再点一次即可」

**与上游 V2.5.x 的对应关系**：上游 V2.5.0（`ffa1056f`）**同方向重做，实现更完整**，采用上游版：
- `_noThink`（标识符都撞了）＋ 只对 DeepSeek 系关思考（`_dsThinkOffM`），目标不认 thinking 字段则去参重试（`_noThinkOff`）；
- 真因链 `_sumWhyM`：每次尝试先清空、失败出口逐条写明（未启用 / 找不到频道 / 读记录失败 / 没 Key / 封档线变了 / 空内容）；
- 空正文按 finish_reason 区分（`_finTruncM`）：截断且正文空 → 提示输出上限耗尽并自动用 16384 再试一轮；
- 「立即更新」重做取窗逻辑，窗口外已无新消息时直说（对应我们 H5 的诉求）。

**撤下结论**：我们 H3a/H3c/H4/H5/H6k/H7/H8/H9/H10 的「说真因」目标由 `_sumWhyM` 覆盖；H1/H2 的「关思考」由 `_dsThinkOffM` 覆盖。不再需要。

## fix-r7 · 启动等待

**用途**：打开应用后的一段等待期内不让 TA 主动开口；等待期一过交回原有判断（放行那一次免掷概率、不排队补发）；等待期内用户说话与 AI 回复完全不受影响。附带「换设备导入」保全：导入备份时本机的等待三字段（开关/时长/起点模式）以本机为准。

**锚点（12 处，W1–W11b）**：

| 锚点 | 内容 |
|---|---|
| W1 | 镜像专用版本标记 `v262-p-r7`（`mirrorOnly`，提上游的 PR 不含这一处） |
| W2 | 新增模块级 `_hbWaitUntil` / `_hbWaitDone` / `_hbNoRoll` 与 `_hbWaitArm()`（按设置确立/重新确立等待期） |
| W3 | 心跳巡检开头加闸门（在既有判据之前；除 W10 外其后判据一字不改） |
| W4 | 原生唤醒那条路同样加闸门（否则装了原生壳时唤醒径会绕过闸门） |
| W5 | 页面加载后确立等待期（紧随 `loadMP`） |
| W6 | 回到前台重新计时（仅当起点模式含「回到前台」） |
| W7 | 设置界面新增「打开应用后等待」开关 + 等待时长 + 起点模式（插在「主动查岗」之后、卡片内） |
| W8 | 设置初始化：把已存值刷进新控件 |
| W9 | 事件绑定：开关 click / 两个下拉 change（照既有样板） |
| W10 | 随机概率那一行：等待期刚放行的那一次免掷（标记读一次即清） |
| W11a | 导入前：记下本机的等待三字段 |
| W11b | 导入后：把本机的等待三字段写回（导入语义的第一个例外） |

**用户可见文案（原样保留，W7 界面）**：
- 开关标题「打开应用后等待」；说明「开启后，打开应用的一段时间内 TA 不会主动开口；等待期一过就交回原有判断——这段时间你没说话，它便照常开口；你已说了话，它就不再插话。不影响你说话与它回复。默认关闭。」
- 等待时长档位：1 / 3 / 5（默认）/ 10 / 15 / 20 / 30 / 60 分钟
- 起点模式：「冷启动与回到前台都算（默认）」/「只算冷启动」
- 提示「冷启动＝把应用完全关掉后再打开；回到前台＝应用还在后台、你切回来的那一次。」
- 提示「留出这段等待，是为了给同步、导入数据留出余裕。」

**与上游 V2.5.x 的对应关系**：上游 V2.5.1（`5104f831`）做了**同向但不同实现**的「打开应用后先安静」（`pres-hb-quiet` / `hbQuietMin`）：
- 挂在定时推送设置里，下拉档位 0（关）/ 2 / 5 / 10 / 15 分钟；开启后打开应用一段时间内不主动开口，不影响说话与回复；
- 上次主动开口时间持久化（`_hbLastFire` 写 `ib_hb_lastfire`）＋ 前台计时（`_hbOpenAt` / 后台时长，离开超过 1 分钟才重置安静窗口）——直接修「换设备后 TA 主动开口」；
- GUIDE 写明使用时机（默认关闭，换设备后先导入备份时用）。

**撤下结论**：我们 W3/W4/W5/W6 的「启动后按住不动、回前台重计」目标由上游 quiet 窗口覆盖；W11a/W11b 的「换设备导入后安静」由上游持久化 + GUIDE 覆盖。我们的功能面（8 档时长、起点模式、免掷）更宽，但按用户拍板**功能上跟上游即可**，不叠回。
