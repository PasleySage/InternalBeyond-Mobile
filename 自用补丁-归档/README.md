## index.html 里相对上游多出来的东西

1. **启动看门狗 + 诊断面板**：启动 12 秒仍未完成（或启动画面仍停留）时弹出面板，含**各步耗时**（`_ibStepLog` / `_ibTimed` 埋点）、就绪判定细节、启动画面心跳、错误原文、失败次数；按钮为「重新加载 / 安全模式重载 / 清离线缓存后重载」；**展示与复制前自动脱敏**（`_ibRedact`：隐去密钥类参数与网址细节）；启动成功会自动收起面板。
2. **`VersionError` 自愈**：库版本比当前页面新（说明拿到旧的离线副本）时，清离线缓存并重载一次（`ib_verfix` 防循环）。
3. **单步超时护栏** `_ibCap` / `_ibTimed`：给启动各步设上限，避免任何一步拖住启动画面。

## ib-sw.js 里相对上游多出来的东西

- **缓存完整性判断**：先看响应是否压缩，压缩响应用"能否完整读完"判断、未压缩才比对 `content-length`，并在入库前**剥掉 `content-encoding` / `content-length`**（否则取出来会被浏览器二次解压、内容损坏）。上游 V2.4.1 的 SW 仍是"`r.ok` 就写缓存"。

## 上游 V2.4.1 已经自己实现的部分（不要再重复搬）

- 预遮罩创建前的"已揭幕"判断（上游用 `_ibVeilOff`，我们用 `__ibVeilOff`）
- 启动画面放行规则：去掉 9 秒硬兜底，改为"已撤遮罩 + 启动完成"，带 20s / 30s 两条兜底（阈值与我们一致）
- `openDB()` 的 `onblocked` 与 `onversionchange`
- `ib-sw.js`：`NAV_TIMEOUT=20000` / `ASSET_TIMEOUT=9000` / `FAST_FALLBACK=3500` + 离线提示页 + 缓存 v3

## 若要在未来某个上游版本上重新套用

1. 以当时的上游 `index.html` 为基准，先确认上面"上游已实现"的清单里哪些**仍然没有**（用锚点正则核对，流程见 skill `upstream-update-brief`）；
2. 只把**上游仍未实现**的部分搬过去：面板（`_ibGuard` + `_ibStepLog`/`_ibTimed`/`_ibRedact` 三个助手 + `_ibVeilStuck`/`_ibMarkOK`）、`VersionError` 自愈、SW 的完整性判断；
3. 面板样式跟随 `ib_m_theme`；脱敏规则见 `_ibRedact`（参数名 + 令牌前缀 + 网址只留首尾标签）。
